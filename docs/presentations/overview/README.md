# Slide deck: the Universal Artifact SDK and the artifact judge/reviewer

> **Audience**: Researchers who write papers, program-committee and artifact-evaluation-committee
> members, and builders of research tools and venue infrastructure. Also anyone presenting the
> project to them.
> **Source of truth for**: The public overview deck that explains what the Universal Artifact SDK
> and the `artifact-judge-reviewer/v1` specification are, why they exist, and how they relate to
> each audience. The specifications themselves remain the source of truth for every rule shown.

## Files

| File | What it is |
|------|------------|
| `build_deck.py` | Single source: slide text, layout CSS, HTML writer, PNG/PDF renderer, and layout checks |
| `deck.css` | Shared stylesheet (generated; system fonts only) |
| `slides/01.html` … `slides/16.html` | One self-contained 1280×720 page per slide (generated) |
| `index.html` | Viewer: arrow keys / PageUp / PageDown / Home / End, or the ◀ ▶ buttons (generated) |
| `slides.pdf` | One 1280×720 page per slide (generated) |
| `thumbs/slide-NN.png` | Rendered image of every slide, for review (generated by a full build; not committed) |

Open `index.html` in a browser; no network access is needed. Generated files carry a
generated marker; edit `build_deck.py` and rebuild instead of editing them.

## Rebuild

```bash
python build_deck.py          # HTML + PNG thumbnails + PDF + layout checks
python build_deck.py --html   # HTML only
```

The render step needs Playwright with Chromium. The build fails if any slide overflows,
clips text, truncates its footer, or uses text smaller than 24px (20px for code and footers).

## Where the examples come from

- **SDK snippets** (slides 3–5): the worked example in the SDK specification (`SPEC.md`,
  Appendix A) and the README quickstart.
- **bGPT paper results** (slides 2, 7, 8, 10, 13): a deterministic paper-adapter and judge run
  on the bGPT paper (spec scenarios E1/E2). The `results.yml`, `claims.yml`, and judge finding
  shown are trimmed copies of real output that follows the published v3/v1 field names.
- **Loss-Free Machine Unlearning table value** (slide 7): a deterministic paper-adapter run
  (spec scenario E4).
- **Reviewer question** (slide 10): illustrative. It was written by hand in the reviewer
  finding format (judge/reviewer spec §5.5); both quotes were checked against the cited pages.
  The "unset" header is the fixed opening of every review draft (§5.12).
- **Run manifest** (slide 11): abridged, in the shape defined by judge/reviewer spec §6.3.
